# ADR 작성 규약

## 파일과 번호

- ADR을 저장소 루트의 `docs/adr`에 둔다.
- 파일명은 `NNNN-kebab-case-title.md` 형식을 사용한다.
- 기존 ADR의 가장 큰 번호 다음 번호를 네 자리로 부여한다.
- 하나의 승인된 작업 브리프를 하나의 ADR로 기록한다.

## 상태와 변경

- 최종 승인 후 작성하는 ADR의 상태는 `승인됨`으로 기록한다.
- 결정이 바뀌면 과거 ADR의 본문을 새 결정처럼 고치지 말고 새 ADR을 작성해 대체 관계를 남긴다.
- 같은 작업을 구현하는 중 추가로 승인받은 결정은 기존 ADR의 `추가 결정`에 덧붙일 수 있다.
- 구현 진행 상황과 파일별 변경 목록은 ADR에 남기지 않는다. 저장소가 `CHANGELOG.md`를 관리하면 거기에, 아니면 작업 결과에 남긴다.

## 템플릿

```markdown
# ADR-NNNN: 제목

- **상태:** 승인됨
- **날짜:** YYYY-MM-DD

## 맥락과 의도

해결하려는 문제, 사용자 의도와 이 결정이 필요한 이유를 적는다.

## 결정

- 합의한 핵심 결정을 이유와 함께 적는다.

## 고려한 선택지

- 실제로 검토한 선택지와 채택하거나 제외한 이유를 간결하게 적는다.

## 범위

- **포함:** 이번 작업에서 수행할 내용
- **제외:** 의도적으로 수행하지 않을 내용

## 완료 기준

- 검증 가능한 완료 조건을 적는다.

## 위임된 결정

- 에이전트가 판단하도록 위임받은 세부사항과 기본 방침을 적는다.

## 결과와 제약

- 선택으로 얻는 효과, 받아들인 트레이드오프와 남은 위험을 적는다.

## 추가 결정

- 구현 중 새로 사용자 승인을 받은 결정이 있을 때만 추가한다.
```

관련 없는 섹션은 억지로 늘리지 말고 `해당 없음`으로 짧게 표시하거나 생략한다.
