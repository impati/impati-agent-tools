# RCA와 다관점 검토

`code-review`에서 읽고 지정된 변경에 관련된 관점만 적용한다. 인터뷰가 없으면 확인 가능한 요구사항과 코드 계약을 근거로 검토하고, 알 수 없는 중요한 기대 동작은 확인 부족으로 남긴다. 기본 검수는 변경 전체의 의도·정확성·회귀·검증을 확인하며, 아래 위험 신호에 해당하는 부분만 심화한다.

## 인과 관계 재구성

코드를 평가하기 전에 작업의 인과 관계를 재구성하라.

### 버그 또는 장애 수정

다음 연결을 확인하라.

```text
관찰된 증상 → 발생 조건 → 직접 원인 → 근본 원인 → 수정 지점 → 기대 결과
```

- 수정이 증상을 가리는 데 그치지 않고 근본 원인을 해결하는가
- 근본 원인에 대한 가정이 코드와 증거로 뒷받침되는가
- 같은 원인이 다른 경로에 남아 있는가

### 기능 또는 구조 변경

다음 연결을 확인하라.

```text
작업 목표 → 핵심 가정 → 변경된 상태·흐름 → 영향받는 소비자 → 실패 가능성
```

- 구현이 작업 목표와 직접 연결되는가
- 암묵적 가정이 유효한가
- 정상 경로뿐 아니라 상태 전이와 실패 경로가 일관적인가

## 커밋별 리뷰

커밋 범위 리뷰이면 각 커밋을 생성 순서대로 검토하라. 미커밋 리뷰이면 커밋별 평가는 해당 없음으로 두고 지정된 변경의 누적 결과를 검토하라.

- 커밋 메시지와 실제 변경 의도가 일치하는가
- 한 커밋이 독립적으로 이해되고 가능한 범위에서 검증·되돌리기 가능한가
- 필요한 구현과 테스트가 함께 있는가
- 이후 커밋이 없으면 깨지는 불완전한 중간 상태를 만들지 않는가
- 승인된 범위를 벗어난 변경이나 우연한 정리가 섞이지 않았는가

커밋 분리 자체가 결함을 만들지 않았다면 단순한 취향 차이는 지적하지 말라.

## 누적 다관점 리뷰

지정된 변경 범위 결과를 다음 두 게이트로 독립 검토하라. 첫 게이트가 통과해도 둘째 게이트를 생략하지 말고, 인터뷰 문구를 그대로 재확인하는 데 그치지 말라.

### 구현 준수 게이트

- 구현이 인터뷰에서 확정한 정책, 책임 경계, 핵심 불변식과 실패 수렴을 지키는가
- 근거 표의 각 테스트 의무가 실제 자동 테스트에 대응하고 현실적인 실패 조건을 재현하는가
- 레포 지침과 승인된 범위·비범위·검증 명령을 지키는가

### 인터뷰·요구사항 완전성 게이트

- 커밋과 누적 diff에서 새로 드러난 호출·데이터 경계를 따라갔을 때 빠진 상태 소유자나 쓰기 권한이 없는가
- 성공, 실패, 결과 불명, 중단 후 재개에서 책임 주체와 수렴 근거가 정해져 있는가
- 중복, 순서 역전, 동시 실행, 재시도, 부분 성공과 데이터 불일치 중 실제 가능한 실패 모드가 누락되지 않았는가
- 대역·어댑터·하위 시스템이 보장하는 계약과 애플리케이션 책임의 경계가 실제 인터페이스에 드러나는가
- 변경의 호출자, 소비자, 다른 서비스·배포 단위와 운영 확인 경로가 빠지지 않았는가

계약이나 소유권이 불명확해 실패 수렴을 보장할 수 없으면 테스트 부족보다 인터페이스·책임 경계 결함을 먼저 보고하라. 외부 상태 변경을 DB 트랜잭션 안에서 실행하면서 결과 조회 계약이나 결과 불명을 복구할 영속 기록이 없다면 트랜잭션·실패 수렴 결함이다. 대역의 내부 맵만 중복을 막고 실제 포트에는 업무 멱등 키나 결과 조회 계약이 없다면 대역 테스트 통과와 무관하게 인터페이스 결함이다. 비동기 소비자가 읽은 오래된 전체 상태를 저장해 동시 변경을 덮을 수 있다면 상태 소유권·쓰기 경계 결함으로 보고, 실제 저장소 조건의 경합 테스트 누락을 별도 검증 근거로 연결하라.

이후 지정된 변경 범위를 다음 관점에서 검토하라. 작업과 관련 없는 관점은 억지로 채우지 말라.

### 의도와 범위

- 작업의 배경과 목표를 충족하는가
- 명시적 비범위나 요청하지 않은 변경을 침범하지 않았는가

### 정확성과 근본 원인

- 핵심 로직과 상태 전이가 모든 관련 경로에서 올바른가
- 수정 지점이 근본 원인과 일치하는가
- 예외, 경계값, 부분 실패와 복구가 빠지지 않았는가

### 영향 전파와 회귀

- 호출자, 소비자, 데이터와 외부 인터페이스에 미치는 영향이 안전한가
- 호환성, 마이그레이션 또는 롤백 문제가 없는가
- 인접 기능에서 예상하지 못한 동작 변화가 생기지 않는가

### 재발 방지와 검증

- 테스트가 구현 세부사항이 아니라 원인과 불변 조건을 검증하는가
- 위험 작업에서 정상 흐름과 단순 예외만 검증하고 응답 유실, 부분 성공, 프로세스 재시작, 중복·역순 사건 또는 실제 저장소 경합처럼 관련 있는 실패 모드를 빠뜨리지 않았는가
- 같은 결함이 다른 경로에서 재발할 가능성이 남아 있지 않은가
- 관측 가능성이나 실패 진단에 필요한 정보가 충분한가

### 설계와 유지보수

- 책임, 추상화와 모듈 경계가 작업 의도에 맞는가
- 불필요한 결합, 중복 또는 변경 확산을 만들지 않았는가
- 미래 변경에서 같은 문제를 반복하기 쉬운 구조가 아닌가

### 상황별 위험

관련 있을 때만 보안, 개인정보, 성능, 동시성, 트랜잭션, 자원 정리와 운영 위험을 검토하라. 원격 상태 변경, 메시지·웹훅·워커, 여러 트랜잭션이나 서비스에 걸친 결과, 병렬 명령, 마이그레이션·순차 배포 또는 신뢰 경계 입력이 보이면 해당 위험을 심화 검토하라.
