# 정책 문서 작성 규약

## 파일과 번호

- 정책 문서를 저장소 루트의 `docs/policy`에 둔다.
- 파일명은 `pd-NNNN-kebab-case-title.md` 형식을 사용한다.
- 문서 ID는 `PD-NNNN` 형식이며 기존 문서의 가장 큰 번호 다음 번호를 네 자리로 부여한다. 첫 문서는 `PD-0001`이다.
- 삭제하거나 대체된 문서의 번호도 다시 사용하지 않는다.
- `PD` 번호는 `BL` 백로그 번호, `ADR` 번호와 완전히 독립적으로 채번한다.
- 정책에는 완료 개념이 없으므로 `done` 같은 하위 디렉터리를 두지 않는다.
- 제목은 정책이 다루는 대상을 짧고 구체적으로 나타낸다.

## 규칙 ID

- 각 규칙에 문서 안에서만 유효한 `PD-NNNN-RN` 형식의 ID를 부여한다. 문서의 첫 규칙은 `R1`이다.
- 한번 부여한 규칙 번호는 재사용하거나 재정렬하지 않는다. 규칙을 빼더라도 남은 규칙의 번호를 당기지 않는다.
- 문서 안에서 규칙을 추가할 때는 마지막 번호의 다음 번호를 쓴다.
- 규칙 ID는 테스트가 개별 규칙을 가리키기 위한 것이다. 규칙이 하나뿐이어도 부여한다.

## 상태와 변경

- 정책 문서는 결정 시점을 고정한다. 결정이 바뀌면 기존 문서의 규칙을 고치지 말고 새 문서를 만든다.
- 새 문서에는 `대체:` 로 이전 문서 ID를, 이전 문서에는 `대체됨:` 으로 새 문서 ID를 한 줄로 남긴다.
- 오탈자, 링크, 표현 정리는 기존 문서에서 수정할 수 있다. 규칙의 내용이 바뀌면 수정이 아니라 대체다.
- 구현 진행 상황, 파일별 변경 목록, 클래스나 함수 이름을 정책 문서에 남기지 않는다.
- 여러 정책의 규칙을 모아 "지금 유효한 규칙 전부"를 주장하는 카탈로그 문서를 만들지 않는다.

## 테스트 주석 표기

- 규칙을 고정하는 테스트의 주석 첫 줄에 규칙 ID를 대괄호로 남긴다. 예: `[PD-0007-R3]`.
- 하나의 테스트가 여러 규칙을 고정하면 관련 ID를 모두 나열한다.
- 표기 위치와 주석 문법은 대상 프로젝트의 언어와 관례를 따른다.
- 규칙 ID만 남기지 말고 그 테스트가 무엇을 잡고 무엇을 잡지 못하는지 한 줄로 함께 적는다.

## 템플릿

```markdown
# PD-NNNN: 제목

- **날짜:** YYYY-MM-DD
- **대체:** 해당 없음

## 배경과 문제

이 정책이 답해야 하는 질문과 정책이 없을 때 생기는 문제를 적는다.

## 정책

- **PD-NNNN-R1:** 검증 가능한 단언 한 문장. 근거를 한 줄로 덧붙인다.
- **PD-NNNN-R2:** ...

## 거절하는 시나리오

- 이 정책 때문에 거절되거나 제한되는 사용자 시나리오를 적는다. 경계에 있는 사례를 우선한다.

## 허용하는 시나리오

- 오해하기 쉽지만 이 정책이 허용하는 시나리오를 적는다.

## 정책이 정하지 않는 것

- 의도적으로 구현에 위임하는 범위를 적는다. 여기 적힌 항목은 구현이 바뀌어도 이 문서를 다시 쓸 이유가 되지 않는다.

## 고려한 대안

- 실제로 검토한 다른 규칙안과 채택하지 않은 이유를 적는다. 구현 방식의 대안은 여기 적지 않는다.

## 재검토 조건

- 이 정책을 다시 볼 조건을 적는다. 관측 가능한 사건이나 시점으로 쓴다.

## 검증

| 규칙 | 무엇이 고정하는가 |
| --- | --- |
| PD-NNNN-R1 | 규칙을 고정하는 테스트 |
| PD-NNNN-R2 | 없음(검증 공백) |

## 미결

- 합의하지 못하고 남긴 사항이 있을 때만 적는다.
```

관련 없는 섹션은 억지로 늘리지 말고 `해당 없음`으로 짧게 표시하거나 생략한다. `정책`과 `검증` 섹션은 생략하지 않는다.
