# ADR-0003: 리뷰 가능한 작업 단위로 커밋

- **상태:** 승인됨
- **날짜:** 2026-08-15

## 맥락과 의도

사용자는 코드를 커밋 단위로 리뷰한다. 따라서 에이전트가 작업을 완료한 뒤 변경 전체를 한 번에 넘기기보다, 각 커밋의 의도와 검증 결과를 독립적으로 이해할 수 있는 단위로 나누어 커밋하고 보고해야 한다.

## 결정

- 작업 완료 후 변경을 독립적으로 리뷰하고 되돌릴 수 있는 논리 단위로 나누어 커밋한다.
- 커밋 단위는 에이전트가 작업 의도와 의존 관계를 기준으로 정한다.
- 대상 프로젝트의 커밋 컨벤션을 우선하고, 별도 규칙이 없으면 Conventional Commits 형식을 사용한다.
- 현재 작업과 무관한 기존 변경은 커밋하지 않는다.
- 완료 보고에는 커밋별 해시, 메시지, 변경 의도와 검증 결과를 포함한다.

## 고려한 선택지

- 파일 종류별로 기계적으로 나누는 방식은 각 커밋이 불완전해질 수 있어 채택하지 않았다.
- 모든 변경을 한 커밋으로 만드는 방식은 리뷰 단위가 커질 수 있어 기본 방식으로 채택하지 않았다.
- 구현 의도와 독립적인 검증·되돌리기 가능성을 기준으로 나누는 방식을 채택했다.

## 범위

- **포함:** 작업 변경의 스테이징, 논리 단위 커밋, 커밋별 완료 보고
- **제외:** 원격 저장소 push, 브랜치 생성, PR 생성

## 완료 기준

- `start-work` 스킬에 커밋 계획, 안전한 스테이징, 논리 단위 커밋과 보고 절차가 포함된다.
- 현재까지의 프로젝트 상태가 하나의 초기 기준 커밋으로 생성된다.

## 위임된 결정

- 각 작업의 구체적인 커밋 개수와 경계는 리뷰 가능성과 의존 관계를 고려해 에이전트가 정한다.
- 별도 로컬 컨벤션이 없을 때 사용할 커밋 메시지의 세부 문구는 에이전트가 정한다.

## 결과와 제약

사용자는 커밋별 의도와 검증 결과를 기준으로 리뷰할 수 있다. 변경이 서로 강하게 얽혔거나 기존 사용자 변경과 겹치면 안전한 분리를 위해 추가 확인이 필요할 수 있다.
