# ADR-0002: 로컬 프로젝트 규칙 우선

- **상태:** 승인됨
- **날짜:** 2026-08-15

## 맥락과 의도

공통 하네스의 작업 원칙이 모든 프로젝트의 고유한 환경과 관례를 정확히 반영할 수는 없다. 프로젝트마다 다른 기술, 명령, 제약과 작업 방식이 적용될 수 있으므로 충돌 시 실제 작업 대상의 로컬 컨텍스트를 보존해야 한다.

## 결정

- 하네스 규칙은 여러 프로젝트에서 사용할 공통 기본값으로 취급한다.
- 하네스와 작업 대상 프로젝트의 로컬 규칙이 충돌하면 더 구체적인 로컬 프로젝트 규칙을 우선한다.
- 로컬 규칙에는 대상 프로젝트의 `AGENTS.md`, 설정, 문서화된 관례, 도구 체인과 검증 명령이 포함된다.
- 시스템·개발자·안전 정책과 현재 사용자의 명시적 요청은 이 결정의 대상이 아니며 로컬 규칙으로 덮어쓰지 않는다.

## 고려한 선택지

- 하네스를 항상 우선하면 일관성은 높지만 프로젝트별 의도와 제약을 훼손할 수 있어 채택하지 않았다.
- 로컬 프로젝트를 우선하면 공통 기본값이 일부 달라질 수 있지만 실제 작업 컨텍스트에 맞는 행동을 보장할 수 있어 채택했다.

## 범위

- **포함:** 하네스 규칙과 대상 프로젝트의 규칙·설정·관례 사이의 충돌 해결
- **제외:** 시스템 및 안전 정책, 현재 사용자의 명시적 지시 사이의 우선순위 변경

## 완료 기준

- `AGENTS.md`에 로컬 프로젝트 우선 원칙과 적용 경계가 명시된다.
- 변경 의도와 핵심 결정이 `CHANGELOG.md`에 기록된다.

## 위임된 결정

- 로컬 환경의 구체적인 예시와 안전 경계의 표현은 사용자의 의도를 유지하는 범위에서 에이전트가 정한다.

## 결과와 제약

하네스를 재사용하면서도 프로젝트별 작업 방식을 보존할 수 있다. 충돌 여부가 불명확하면 제1원칙에 따라 사용자에게 확인해야 한다.
