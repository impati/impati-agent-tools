# ADR-0001: 작업 시작 인터뷰 도입

- **상태:** 승인됨
- **날짜:** 2026-08-15

## 맥락과 의도

에이전트가 개발 과정에서 사용자의 의도와 다른 결정을 내리지 않도록, 구현 전에 충분한 인터뷰로 컨텍스트와 결정 사항을 맞출 필요가 있다. 처음부터 완벽한 질문 경계를 정하기보다 실제 사용을 통해 조정한다.

## 결정

- 변경 작업 전에 `start-work` 스킬로 사용자의 의도, 범위, 주요 결정과 완료 기준을 인터뷰한다.
- 결과에 영향을 주는 결정은 선택지와 추천 이유를 제시하고 사용자에게 확인한다.
- 구현 중 새로운 중요한 결정이 나타나도 사용자 승인 후 진행한다.
- 승인된 인터뷰 결과는 `docs/adr`에 ADR로 남긴다.
- 자동 실행을 기본으로 하되, 누락 시 사용자가 `$start-work` 또는 작업 시작 인터뷰 요청으로 명시적으로 실행할 수 있게 한다.

## 고려한 선택지

- 모든 미세 구현 결정을 질문하는 방식은 통제력은 높지만 작업을 지나치게 느리게 할 수 있어 채택하지 않았다.
- 중요한 결정을 중심으로 질문하고 가역적인 세부사항은 위임 방침을 명시하는 방향을 채택했다.
- 인터뷰 결과를 채팅에만 두는 대신 이후 세션에서도 의도를 확인할 수 있도록 ADR로 보존하기로 했다.

## 범위

- **포함:** 코드, 설정, 문서 등 저장소 변경 전 인터뷰와 ADR 기록
- **제외:** 조회, 설명, 상태 확인처럼 저장소를 변경하지 않는 요청

## 완료 기준

- `start-work` 스킬이 자동 또는 명시적으로 발견된다.
- 최종 승인 전에는 구현하지 않고, 승인 후에는 ADR을 먼저 작성한다.
- 구현 중 새로 발생한 중요한 결정도 사용자에게 질문한다.

## 위임된 결정

- 스킬 이름, 질문 순서, ADR의 세부 템플릿은 위 의도를 유지하는 범위에서 에이전트가 정한다.
- 결정 경계와 인터뷰 깊이는 실제 사용 피드백에 따라 조정한다.

## 결과와 제약

작업 시작 속도보다 의도 정렬과 사용자 결정권을 우선한다. 작은 작업에서도 인터뷰 비용이 생길 수 있으며, 반복 사용을 통해 불필요한 질문과 빠진 질문의 경계를 개선해야 한다.
